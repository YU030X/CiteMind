# scripts/AGENTS.md

本目录用于可复用的开发辅助脚本和质量门禁。Python 后端行为以 pytest 测试；Node 脚本只承担前端工具链或明确批准的开发期辅助能力，不进入产品运行时。脚本应能从明确的仓库入口重复运行，并在失败时给出可定位的原因。仓库级约束仍见根目录 `AGENTS.md`。

## 执行与路径

- Python 脚本调用其他进程时，使用 `subprocess` 参数数组和 `shell=False`；调用当前环境的 Python 使用 `sys.executable`，不要拼接命令字符串。
- Node 脚本使用标准库处理文件和进程；开发期外部服务凭据只从服务端环境变量读取，不接受前端公开变量或写入日志。
- 在接收仓库相对 glob 路径时统一规范为 `/` 分隔符，之后的匹配使用同一表示。
- 平台差异由确实需要它的门禁处理；不要为少量路径或进程差异建立共享平台适配层。

## 源码归属门禁

- 识别源码归属时使用理解目标语言语法的发现方式，不能只靠易误判的文本搜索。
- 对空语料或意外缩小的扫描范围直接失败，避免门禁因漏扫而通过。
- 每一种会改变识别边界的纳入形式和排除形式都要有测试；新增规则时同步补充对应样本。

## 脚本规格测试

- 按规格测试可能在独立 worker 中运行，并与套件内其他测试及同一 CI job 的其他门禁并行；从一开始就按并行执行设计。引入实际测试运行器后，在测试策略中记录其执行模型。
- 每个规格测试独占并清理自己获取的端口、临时路径和子进程；使用唯一资源名，并在成功、失败及超时时都完成清理。
- 只在单独运行时通过的规格测试视为测试缺陷，修复资源隔离或生命周期后再接受。
